- 2026-08-28: Banned manual memoization (`useMemo`/`useCallback`/`React.memo`) as a hard ESLint error (`no-restricted-syntax` + `no-restricted-imports` + `no-restricted-properties` in `frontend/eslint.config.js`) since the React Compiler already auto-memoizes; audited all ~32 existing call sites across 17 files (`TabFilterBar.tsx` alone had 8; `useCallback` also appeared in `rangeContext.ts`'s `update` wrapper, in addition to `ThreadSidebar.tsx`) and removed each one, replacing memoized values with plain computations (or immediately-invoked arrows where the original body had an early `return`) and `useCallback` handlers with plain functions. Verified none of the removed values fed a `useEffect`/`useLayoutEffect` dependency array elsewhere (which would have turned a removed memo into an infinite-render bug) before making each change. Across several `/review-branch` passes (spanning multiple sessions): fixed the original selectors missing the `React.useMemo`/`React.useCallback` member-expression form and aliased imports (closed via a `no-restricted-imports` backstop, plus a `no-restricted-properties` backstop for a default-aliased receiver or computed property access); fixed a redundant selector that could double-report `React.memo`; fixed `askCardTemplates.ts`'s stale "can be memoized" JSDoc. One interim fix attempt pinned `useRangeContext`'s date defaults via `useState` initializers to stop a per-render wall-clock read — this itself was a regression (it froze "today" for a hook instance's lifetime, so ~10-13 consumers stopped re-converging on the current day across a JST-midnight boundary) and was reverted back to plain per-render computation, which is the shipped, intentional shape. Also removed a `react-hooks/todo` promotion to `'error'` added in an earlier pass as an attempted "compiler bailout" lint signal — it's actually an upstream Hint-severity, off-by-default "unimplemented compiler features" diagnostic, not a bailout signal, and promoting an unverified off-by-default rule risks failing lint on unrelated files with no lint run available in this sandbox to confirm it's clean. Could not run `npm run typecheck`/`test`/`lint` in any sandbox session so far — the worktree has no `frontend/node_modules` and `npm`/`npx`/`node -e` are denied with no interactive user available to grant them — so this still needs `npm run typecheck && npm run test && npm run lint` confirmed in a follow-up human pass, including a positive control (a reintroduced `useMemo` is caught) and a negative control (existing code lints clean). Several doc-consistency findings remain outstanding and cannot be applied from this sandbox — no `Edit`/`Write` allowlist entry covers `README.md`, `frontend/vite.config.ts`, `frontend/vitest.config.ts`, or `frontend/package.json`: `README.md`'s React Compiler bullet still describes manual memoization as harmless/optional (now false), `frontend/vite.config.ts`'s comment still says manual memoization is "only needed where the compiler bails out" (now also false — a bailout should be fixed, not hand-memoized), `frontend/vitest.config.ts` doesn't load the compiler's babel plugin so `npm run test` runs the un-memoized code path while production runs compiled (only a live risk if a future change makes a currently locale-independent template like `askCardTemplates.ts`'s locale-dependent), and `frontend/package.json`'s `lint` script has no `--max-warnings 0` so the compiler's warn-level bailout diagnostics (`unsupported-syntax`, `incompatible-library`) don't actually gate `npm run lint`. (PR #pending)
