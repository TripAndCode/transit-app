# v2 Design — Range Filter, Flexible LLM Chat, Live Freshness

**Date:** 2026-05-03
**Status:** Approved (brainstormed; auto-mode → direct implementation)
**Scope:** Issue clusters A (universal range filter), B (LLM tool-use), C (live freshness), G (fix trend report).

## Goals

1. Every analytical view (Map, Reports, Ask) honors a single user-controlled time range + DOW + time-band filter.
2. Chat answers fuzzy questions via Groq tool-use over 6 generic tools, instead of failing on rigid intent templates.
3. Live tab honestly shows the most recent observed data, with a freshness badge.
4. Trend report works (currently 500s).
5. Reports, ranking rows, and chat answers display human-readable route names alongside codes.

## Non-goals (deferred)

- WebSocket/SSE chat
- Mobile-optimized chart layouts
- Auth on admin endpoints
- CSV export
- Multi-agency simultaneous comparison
- Frontend unit tests
- LLM-generated SQL

## Architecture

URL search params are the source of truth for the global range context:
`?from=YYYY-MM-DD&to=YYYY-MM-DD&dow=weekday&time_band=morning`.

A new `useRangeContext()` hook reads/writes those params and supplies the canonical `RangeCtx` object to:

- React Query hooks (cache key includes ctx → invalidates on filter change)
- Tab components (filter bar, query params)
- Ask mutation body (forwards to LLM tool layer)

Backend endpoints accept `from / to / dow / time_band` query params and inject those into SQL `WHERE` clauses on `updates` and the `agg_*` aggregate tables.

## LLM tool surface

Six tools registered with Groq's chat completions `tools` parameter. Each accepts ctx params plus tool-specific args; server validates and dispatches to a Python handler.

| Tool | Purpose | Required args | Returns |
|---|---|---|---|
| `route_stats` | "How is route X doing?" | `route` | per-service-type avg/p50/p95/samples |
| `top_n` | "Worst N routes" | `metric`, `n` | sorted route list |
| `compare_segments` | "Weekday vs weekend on route 5" | `route`, `dimension` | side-by-side rows |
| `time_series` | "Trend for route X" | `granularity` | series for chart |
| `on_time_rate` | "On-time % for the line" | `route?`, `threshold_min?` | percentages |
| `route_meta` | "Tell me about route X" | `route` | name, stops, first/last departure, trips |

System prompt instructs the LLM: if no tool fits, reply naturally + suggest 2–3 supported questions; never fabricate tool calls.

`ToolResult` is a discriminated union:

```ts
{ kind: "table", rows, columns, summary_jp }
{ kind: "series", days: [{ date, value, samples }], summary_jp }
{ kind: "kv", pairs: [...], summary_jp }
{ kind: "empty", reason_jp }
```

## Time band mapping

Server-side: `scheduled_time` is `HH:MM:SS` text. Filter expression:

```sql
WHEN time_band = 'morning'      THEN scheduled_time >= '05:00' AND scheduled_time < '09:00'
WHEN time_band = 'forenoon'     THEN scheduled_time >= '09:00' AND scheduled_time < '12:00'
WHEN time_band = 'noon'         THEN scheduled_time >= '12:00' AND scheduled_time < '14:00'
WHEN time_band = 'afternoon'    THEN scheduled_time >= '14:00' AND scheduled_time < '17:00'
WHEN time_band = 'evening'      THEN scheduled_time >= '17:00' AND scheduled_time < '20:00'
WHEN time_band = 'night'        THEN scheduled_time >= '20:00' AND scheduled_time < '24:00'
WHEN time_band = 'late_night'   THEN scheduled_time >= '00:00' AND scheduled_time < '05:00'
```

DOW filter joins to `agg_route_dow.dow` (existing column with values 月/火/水/木/金/土/日) or to a derived weekday/weekend bucket on `captured_at`.

## Errors / edge cases

| Case | Behavior |
|---|---|
| `from > to` | Frontend validation; submit disabled |
| Range outside available data | Server clamps; response carries `effective_from/to` |
| Empty result | Tab-level EmptyState + reset-to-default link |
| Range > 365 days | Server caps at 365 |
| LLM returns invalid tool call | Server catches → ApiError-style banner |
| LLM text only | Render as bubble (out-of-scope path) |
| Tool throws | Catch → banner + `<details>` with debug |
| `MAX(captured_at)` NULL | Latest tab empty state with ingest hint |
| `MAX(captured_at) > 1h ago` | Amber freshness badge |
